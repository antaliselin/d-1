## 0　摘要

**这段要回答**：这个系统在整局里负责什么，不负责什么，谁依赖它。

### 0.1　一句话职责

这里的容器指的是客人带过来的手提箱，不管他是什么，在程序里面就是：

一张 长x宽  `cols × rows` 的表格 以及额外一个不可用格子的表格

### 0.2　不做什么【范例】

| 不做                                 | 谁做                       |
| ------------------------------------ | -------------------------- |
| 不判断物品值多少钱、是否属于客人偏好 | S05 结算                   |
| 不处理拖拽手势、不决定松手后算什么   | S03 拖拽与交互             |
| 不生成客人和箱子规格，包括不可用格子 | S04 客人与特殊客人         |
| 不决定客人自带什么、带几件、放在哪   | S04 客人与特殊客人         |
| 不画格子、不播动画                   | 客户端表现（不单独出文档） |

### 0.3　依赖

- 上游依赖：**无**。容器是纯数据 + 纯函数，不读时间、不读随机、不碰界面。这一条要守住，否则没法单测。
- 下游使用者：S02 物品与库存、S03 拖拽与交互、S05 结算（用 `placeableCount` 算填充率）。

### 0.4　验收标准

一句话：**给定容器、形状、锚点，任意时刻都能立刻回答能不能放，且永远不出现重叠、越界、落在不可用格子。**

可测三条：

1. 1000 次随机放置尝试，0 次出现两件物品占同一格。
2. 10×10 容器上每次移动重算的耗时 < 1ms。
3. 任何非法操作都返回 `false`，不抛异常、不写坏状态。

## 1　数据

**这段要回答**：有哪些字段，类型是什么，谁写谁读。

### 1.1　容器

| 字段      | 类型           | 默认    | 含义                                             | 谁写           |
| --------- | -------------- | ------- | ------------------------------------------------ | -------------- |
| `cols`    | int            | —       | 列数（6~10）                                     | S04 生成时写死 |
| `rows`    | int            | —       | 行数（6~10）                                     | 同上           |
| `blocked` | string[]       | `[]`    | 破洞格，写作 `"x,y"`，如 `"5,0"`                 | S04 生成       |
| `cells`   | (id \| null)[] | 全 null | 长度 `cols*rows`，下标 `y*cols+x`，存物品实例 id | 只由本系统改   |

**关键约束**：`cells` 里存的是 **实例 id**（`instanceId`），不是物品定义 id（`itemId`）。同一件物品摆两次要有两个实例 id，否则移除时会连带删掉另一件。

### 1.2　形状与旋转

| 字段    | 类型               | 含义                                                 |
| ------- | ------------------ | ---------------------------------------------------- |
| `cells` | `{x,y}[]`          | 物品未旋转时占的格，相对左上角；允许中间有洞（异型） |
| `rot`   | `0 \| 1 \| 2 \| 3` | 顺时针转过的四分之一圈数                             |
| `Shape` | `{w,h,cells}`      | 某个朝向下的包围盒 + 实际占格                        |

### 1.3　常量【范例】

| 常量                    | 值     | 说明                       |
| ----------------------- | ------ | -------------------------- |
| `CONTAINER_MIN` / `MAX` | 6 / 10 | 行列数上下限，越界直接抛错 |
| 磁吸半径                | 1 格   | 见 2.6                     |

> 拖拽阈值、容器外容差属于 **S03 拖拽与交互**，不在本系统（1.3 早期版本曾放在这里，已移走）。本系统只负责"给定格子和形状，判能不能放"，不负责"手指移动多少才算拖拽"。

### 1.4　破洞格的表示

- 字符串 `"x,y"`，创建时**去重**。
- **越界坐标**（如 `"99,99"`）不报错、不占位：合法性判定先查越界，轮不到破洞。
- 破洞格与普通空格的区别：破洞**永远不能放**，视觉上要能看出来（见 7.1）。

## 2　规则

> 脚哥：基本由ai根据demo生成，已审阅，但我不敢动也看不懂，但和demo应该大差不差

### 2.1　索引与越界

```text
index(x, y)  = y * cols + x
inside(x, y) = 0 <= x < cols 且 0 <= y < rows
```

格子状态只有四种：`outside`（越界）/ `blocked`（破洞）/ `occupied`（被占）/ `free`（可放）。

### 2.2　旋转

顺时针 90°，公式（`h` 是**旋转前**的包围盒高）：

```text
(x, y) → (h - 1 - y, x)
rot 个四分之一圈 = 连续调用 rot 次
```

例子：`["##", "#."]`（3 格，包围盒 2×2）转一次 → `["##", ".#"]`。

**注意**：转 4 次一定回到原形，但**转 2 次不一定**（不对称形状要单独测）。

### 2.3　包围盒

```text
w = max(所有 cell.x) + 1
h = max(所有 cell.y) + 1
```

**不要**用「字符串行长度」算宽度，否则尾部的 `.` 会把包围盒撑大，物品看起来缩在一角。

### 2.4　合法性 `canPlace`

```text
canPlace(grid, cells, ignoreId = null):
    for cell in cells:
        if not inside(cell):            return false   // 越界
        if isBlocked(cell):             return false   // 破洞
        occupant = grid.cells[cell]
        if occupant != null and occupant != ignoreId:  return false  // 被占
    return true
```

`ignoreId` 用于「移动/旋转自己」：忽略自己原来占的格，否则原地转一下都会被判非法。

### 2.5　锚点夹取 `clampAnchor`

锚点 = 拼图**左上角**所在格。

```text
anchor.x = clamp(round(x), 0, cols - shape.w)
anchor.y = clamp(round(y), 0, rows - shape.h)
```

先夹取再判合法性——否则「拖到边上被夹回来其实放得下」会被误判成红格。

### 2.6　磁吸 `nearestValidAnchor`

**允许手指歪一格**：夹取后的锚点放不下时，向外一圈找最近的可放锚点，半径 = 1。

```text
a = clampAnchor(x, y)
if canPlace(a): return a
for ring = 1..radius:
    候选 = 环上所有 (a.x+dx, a.y+dy)，每个先 clamp 再判合法
    取曼哈顿距离 |dx|+|dy| 最小的；距离相同按扫描顺序：上 → 左 → 右 → 下
    if 找到: return 候选
return null    // 交给调用方显示红格
```

**【待写】** 同距离的取舍顺序（当前是「歪一点会向上吸」）是否符合手感？实机试过后填结论，不行就改顺序——但改完要同步这条规则，别让代码和文档打架。

### 2.7　放置 / 移除 / 移动

三个操作都返回**新的 Grid**，不修改入参：

```text
place(grid, instanceId, cells)  // 调用方必须先过 canPlace；这里只写格
remove(grid, instanceId)        // 把所有等于该 id 的格置 null
move(grid, id, cells) = place(remove(grid, id), id, cells)
```

### 2.8　统计

```text
placeableCount = cols * rows - 破洞数        // 与占用无关
occupiedCount  = cells 里非 null 的个数
fillRatio      = occupied / placeableCount   （分母为 0 时返回 0，不要除零）
```

> 注意：客人自带物品占的格要**从填充率分母里扣掉**，但那属于 S05 结算的算法，本系统只提供原始的 `placeableCount` 和 `occupiedCount`。

### 2.9　角标定位（异型物品专用）

UI中，物品左上角要挂「谁的货」标记，右下角要挂「剩余发数」角标。异型物品的包围盒角上可能是缺口，直接贴角会飘在空格里，所以：

- 左上角标记：沿包围盒最左一列往下找，落在第一个真正被占的格；
- 右下角角标：沿包围盒最下一行往左找，落在第一个真正被占的格。

## 3　状态与流程

**这段要回答**：容器从出现到消失经历什么，谁在什么时候调谁。

### 3.1　生命周期

```text
创建 createGrid(spec)
  └─ 注入客人自带物品（可选，S04 算位置，本系统 place）
       └─ 上台（可能延迟：客人说完某句话才把箱子放上来）
            └─ 营业中：放置 / 移动 / 旋转 / 收回（反复）
                 └─ 成交或客人离开 → 销毁（一次性，不复用）
```

### 3.2　物品一次放置的完整时序

```text
手指按下 → 记录起点、实例 id、当前 rot
手指移动（超过 S03 的拖拽阈值才算拖拽）→ 生成跟手半透明幽灵物品 ghost
     ↓ 换算指针所在格 cellFromPoint()
     ↓ 若超出 S03 的容器外容差：隐藏 ghost，anchor = null
     ↓ clampAnchor() → 得到候选锚点
     ↓ canPlace(cells, ignoreId=自己) → valid
     ↓ 显示落点预览：valid 绿 / 非法 红；ghost 变淡
手指抬起
     ↓ valid → place()，库存 -1（S02）
     ↓ 非法 → 不落地，按 S03 的规则回货架或悬空
```

### 3.3　客人自带物品的注入

容器只提供「注入」这一个动作，不参与任何决策。

```text
injectStartItems(grid, items) -> {ok: true, grid} | {ok: false, reason, index}
    items = [{instanceId, shape, rot, x, y}]   // 由 S04 算好，按给定顺序
    逐件 canPlaceAt：失败立即整体回滚，返回失败的是哪一件（index）
```

- 带什么、带几件、朝向、落点、总占格比例（可用格的 20%~50%）、放不下时重摇还是换小件——**全部是 S04 的规则**，不在这里。
- 容器不排序、不重摇：一旦引入随机，就不再是纯函数，同一种子无法复现（见 0.3）。
- 一批自带物品**要么全进去、要么整体失败**，不做部分成功；否则同一颗种子在不同实现里会生成不同的难度。
- 注入只写格子、不写归属：`owner = customer` 是 S02 物品实例上的字段。

### 3.4　容器延迟上台

有的客人要问完话才把箱子放上台。实现上是「容器已创建但不可交互」，不是「没容器」——这两者在 UI 上表现不同（前者显示空台面，后者不显示容器框）。

### 3.5　与其它系统的接口

| 本系统提供                               | 给谁       | 用途             |
| ---------------------------------------- | ---------- | ---------------- |
| `canPlace` / `place` / `remove` / `move` | S02、S03   | 放置与交互       |
| `injectStartItems`                       | S04        | 注入客人自带物品 |
| `placeableCount` / `occupiedCount`       | S05        | 填充率           |
| `cellsOf` / `shapeOf`                    | 客户端表现 | 渲染拼图与角标   |
| `clampAnchor` / `nearestValidAnchor`     | S03        | 拖拽吸附         |

## 4　交互与表现

**这段要回答**：客户端要画什么、画在哪一层、什么时候变。

### 4.1　层级（从下到上）

```text
容器底图 → 格子线 → 已放物品 → 落点预览(ghost) → 跟手幽灵 → 气泡/对白 → 面板 → 遮罩
```

层级由客户端表现规范统一规定，本节只保证：**落点预览必须在物品之上、跟手幽灵之下**，否则玩家看不见要放哪。

### 4.2　坐标换算

- `cellFromPoint(px, py)`：把屏幕坐标换成格子坐标，**地板取整**（不是四舍五入），否则格子中心附近会跳格。
- 容器外容差（数值见 S03）：手指稍微出框仍算在容器内，减少"明明还在框里却说放不下"的挫败。
- 格子边长由客户端表现定（原型 24px）：一格就是最小命中区，小于这个尺寸的点击目标不要做。

### 4.3　颜色语义

| 状态     | 颜色       | 说明                                     |
| -------- | ---------- | ---------------------------------------- |
| 合法     | 绿         | 落点预览                                 |
| 非法     | 红         | 越界 / 破洞 / 重叠，三者同色，不区分原因 |
| 吸附成功 | ghost 变淡 | 表示"已经吸到格子上了"，不是"放下了"     |

### 4.4　输入优先级（手指同时压着多个东西时）

```text
投放区（事件/派遣面板）  >  客人立绘（治疗）  >  另一件物品（装弹/合成）  >  空格子（落位）
```

顺序写死，否则压着枪和压着格子会打架。

### 4.5　动画与时长

| 事件     | 表现               | 时长 |
| -------- | ------------------ | ---- |
| 拖拽跟随 | ghost 跟手，无延迟 | 0    |
| 吸附     | ghost 透明度变化   | 0    |
| 放置     | 无补间，立即到位   | 0    |
| 旋转     | 立即改变形状       | 0    |
