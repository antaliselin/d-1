## 0　摘要

**这段要回答**：这个系统在整局里负责什么，不负责什么，谁依赖它。

### 0.1　一句话职责

定义三件事：**一件物品是什么**（定义表）、**这一件是什么**（实例）、**货架上还剩多少**（库存），外加多件物品碰到一起时的规则：**装弹、合成、治疗消耗、条件协同**。

### 0.2　不做什么

| 不做                                     | 谁做               |
| ---------------------------------------- | ------------------ |
| 不判断这东西能不能放进容器、放在哪里     | S01 网格与容器     |
| 不算这件货值多少钱、是否属于客人需求物品 | S05 结算           |
| 不关心客人带什么、预算多少               | S04 客人与特殊客人 |
| 不处理拖拽手势、不决定松手后落哪         | S03 拖拽与交互     |
| 不画图标、不做数字角标                   | 客户端表现         |

### 0.3　依赖

- 上游依赖：**无**。物品定义是静态表，实例与库存是纯数据，不读时间、不读随机。
- 下游使用者：S01（拿 `cells` 算形状）、S03（拖拽时读写实例）、S04（生成客人自带物品）、S05（价值、弹药按发计、装弹增值、条件协同）。

### 0.4　验收标准

一句话：**任何操作都不会凭空造货、也不会凭空灭货；弹药永远按「发」记账。**

可测三条：

1. 任意操作后，对每件 shop 物品都满足：`库存 + 箱内 + 手上 + 枪内 = 常量`（普通物品按件，弹药按发）。
2. 装弹 N 发后，枪内发数 +N，且来源（货架 / 箱内那件 / 手上那件）恰好 −N。
3. 库存永远不会变成负数。

## 1　数据

**这段要回答**：有哪些字段，类型是什么，谁写谁读。

### 1.1　物品定义 `ItemDef`（静态表，77 条）

| 字段               | 类型               | 含义                                                                               | 谁写   |
| ------------------ | ------------------ | ---------------------------------------------------------------------------------- | ------ |
| `id`               | string             | 程序用的唯一键，如 `pistol`、`ammo_pistol`                                         | 策划表 |
| `name`             | string             | 显示名                                                                             | 策划表 |
| `tags`             | {enum}[]           | 标签数组，见 1.4                                                                   | 策划表 |

| `rounds`           | int?               | 一盒弹药装几发，弹药必须要有这个字段。注意从仓库拿去弹药时会一次性拿出rounds发子弹 | 策划表 |
| `magazine`         | int?               | 弹匣容量；有它才能被装弹                                                           | 策划表 |

| `art`              | string             | 贴图引用                                                                           | 客户端 |
| `connectItem_type` | `{enum,int}[]?`    | 与哪些**标签**协同、加多少瓶盖，见 2.9                                             | 策划表 |
| `connectItem_id`   | `{string,int}[]?`  | 与哪些**物品 id** 协同、加多少瓶盖，见 2.9                                         | 策划表 |
| `craftWith`        | `{string,string}?` | 字段1是这个物品能和id进行合成，字段2为产物                                         | 策划表 |

> 脚哥：以防你不知道带 `?` 的是可选字段。

**关键约束**

- `tags` 是**数组**，一件物品可以有多个标签（例如「子弹 + pistol」）。同一件物品的**口径标签恰好一个**或没有。
- `value` 是**整数瓶盖**，弹药按「一发」计价，一整盒的价 = `value × rounds`。单价直接填，不由盒价折算。
- 物品的开局数量**不在这里**，见 1.5。

### 1.2　物品实例 `ItemInstance`

| 字段           | 类型        | 含义                                        | 谁写          |
| -------------- | ----------- | ------------------------------------------- | ------------- |
| `instanceId`   | string      | `it-0`、`it-1`…… 全局递增，可预测，不会重复 | 本系统        |
| `itemId`       | string      | 指向定义表                                  | 创建时        |
| `owner`        | enum        | `shop`（玩家的货）/ `customer`（客人自带）  | 创建时        |
| `rot`          | 0~3         | 朝向                                        | S03 旋转时    |
| `rect`         | `{x,y,w,h}` | 锚点 + 旋转后的包围盒                       | S01 放置时    |
| `rounds`       | int?        | 弹药剩余发数（只有弹药有）                  | 装弹 / 消耗时 |
| `magRounds`    | int?        | 枪内已装发数（只有枪有，0 = 空枪）          | 装弹时        |
| `loadedAmmoId` | string?     | 装进去的是哪种子弹                          | 装弹时        |

**实例只存状态，不存派生值**：枪里装了多少发记在 `magRounds`，值多少钱由 S05 按 `弹.value × magRounds` 现算，不在实例上缓存金额。

**关键约束**：`instanceId` 不是 `itemId`。同一件物品摆两次必须是两个实例，否则移除一件会连带删掉另一件。

## 2　规则

**这段要回答**：算法到底是什么。全部是纯函数，输入旧状态、返回新状态。

### 2.1　库存守恒

一条式子，所有操作都不能破坏它：

```text
对每件 shop 物品：
    库存 + 箱内该物品的件数 + 手上那件 + 枪内子弹（按发）
  = 初始库存（此后只减不增，成交/消耗/被搬走才是唯一出口）
```

**扣库存的时机**：从货架拿出来的那一刻就扣（不是放下的时候）。所以手上悬着的那件**已经不在库存里**了，收回货架时才加回去。

### 2.2　取出 `takeFromStock`

- 如果取出弹药，会一次性拿出rounds发弹药

```text
takeFromStock(def):
    available = stock[def.id]
    if available <= 0: return 0            // 卖光了
    amount = def.rounds != null
             ? min(def.rounds, available)  // 弹药最多拿一盒
             : 1
    stock[def.id] -= amount
    return amount                          // 弹药返回的是「发数」
```

### 2.3　归还 `refundToStock`

普通物品加 1 件；弹药按剩余发数加回去（打剩 12 发就还 12 发），不会凭空变回一整盒。

装入子弹的枪归还时，子弹一起归还：

```text
refundPlacedToStock(placed):
    if 是枪 且 magRounds > 0:
        stock[loadedAmmoId] += magRounds      // 子弹按「发」回库
        magRounds = 0；loadedAmmoId = null
    stock[itemId] += 1                        // 枪本身 +1 件
```

- 只对 `owner = shop` 生效；客人的枪不能收回货架，不存在这一条。
- 回去的是「当初装进去的那一种子弹」，用 `loadedAmmoId` 记，**不按枪的口径去猜**。

### 2.4　实例化 `newInstance`

```text
id = `it-${instanceSeq}`;  instanceSeq += 1
rounds    = (有 rounds)   ? 取到的发数 : null
magRounds = (有 magazine) ? 0 : null        // 枪出厂是空枪
owner     = shop | customer
```

递增序号保证可预测，测试可以断言具体 id。

### 2.5　装弹

**触发**：把弹药拖到枪上。

```text
条件（全部满足才成立）:
    来源是玩家的货（owner = shop）       // 不能拿客人的子弹去装
    来源有 rounds 且 > 0                 // 手雷没有 rounds，不算弹药
    目标有 magazine                      // 只有枪能装
    来源与目标的口径标签相同且不为空      // 口径标签在 tags 里，恰好一个
    目标不是「满弹匣」

数量:
    transfer = min(弹匣剩余空间, 来源剩余发数)
    弹匣剩余空间 = magazine - magRounds

结果:
    目标.magRounds += transfer
    目标.loadedAmmoId = 弹.id
    来源扣除 transfer（货架 / 箱内那件 / 手上那件，三选一；减到 0 就销毁）
```

三个要点：

- **客人的枪也能装**：目标可以是任何人的枪，装进去的子弹按普通商品进入结算，还能吃到 2.9 的协同加成。
- **增值不落库**：装了多少发记在 `magRounds`，值多少钱由 S05 现算（`弹.value × magRounds`）。
- **不允许退弹**：子弹装进去就出不来，只能随枪一起被卖掉，或随枪收回货架（2.3）。

### 2.6　合成

**例如**：绿草药 + 红草药（顺序无关）。

```text
条件:
    参与合成的两件物品都有carftWith字段
    参与合成的物品owner字段必须双方都为shop，即不能合成客人的物品

结果:
    两件都消耗，尝试在原地生成一件合成产物
    位置优先沿用「目标」的锚点与朝向；放不下再试朝向 0；都放不下 → 整笔取消，
    两件都不消耗，提示「先把旁边挪开」
```

### 2.7　治疗

**触发**：把医疗用品拖到客人立绘上。

```text
前提：
    物品拥有heal值
    物品的owner 为 shop
结算:
    hp = min(HP_MAX, hp + heal)
    customerHealed += amount        // 供 S05 折算瓶盖奖励
```

两条硬规则：

- **满血时拒绝**，药不消耗（提示「他的生命值已经是满的」）。
- **客人的东西不能拿来给他治**（来源必须是 `shop`）。

### 2.8　归属

| 能力                     | `shop`（玩家的货） | `customer`（客人自带）      |
| ------------------------ | ------------------ | --------------------------- |
| 能放进箱子               | ✅                  | ✅                           |
| 能收回货架               | ✅                  | ❌                           |
| 能卖钱                   | ✅                  | ❌（但装进去的子弹按商品算） |
| 能拿来装弹 / 合成 / 治疗 | ✅                  | ❌                           |

### 2.9　条件协同 `connectItem_type` / `connectItem_id`

**这段在回答**：容器里"有另一件东西"能不能让这件货更值钱。「同口径子弹加成」是它的一个实例，正式版全部由数据表驱动。

**触发**：结算时由 S05 调用，对容器内**每一件要计价的物品**各查一次。

```text
输入:
    D    = 这件物品的定义（含两个 connect 字段）
    T    = 容器内所有物品的标签并集（tags 展开；含客人自带物品）
    I    = 容器内所有物品的 id 集合（含客人自带物品）
    base = 这件货的底价（已按需求相关度算过全额 / 半价）

第 1 步　找搭档：
    hitType = D.connectItem_type 里、键 ∈ T 的条目
    hitId   = D.connectItem_id   里、键 ∈ I 的条目
    先把「自己」从 T / I 里排除，否则一件货会给自己加成

第 2 步　取加成：
    gain = max(hitType 的数值, hitId 的数值, 0)       单位：瓶盖（绝对值）
    cap  = round(base × CONNECT_BONUS_CAP_PCT / 100)
    gain = min(gain, cap)

第 3 步　算钱：
    这件货的最终价 = base + gain
```

四条必须写死的规则：

| #   | 规则                                                                                       | 为什么                                         |
| --- | ------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| 1   | **只认声明方**：A 声明了和 B 协同，只有 A 增值；B 不因 A 的声明而增值（除非 B 自己也写了） | 否则一条数据影响两件货，数值翻倍               |
| 2   | **存在性判定**：箱里有 1 把枪还是 3 把枪，对同一件子弹的加成一样                           | 不允许左脚踩右脚                               |
| 3   | **搭档可以是客人的东西**：客人自带的枪也算"场上有枪"                                       | 好玩                                           |
| 4   | **乘在底价上**：先按需求相关度算全额 / 半价，再取加成                                      | 用不上的东西拿不到大额加成，避免堆协同绕过需求 |

**取值示例**：

| 物品     | 字段               | 取值               | 效果                                                          |
| -------- | ------------------ | ------------------ | ------------------------------------------------------------- |
| 手枪弹盒 | `connectItem_type` | `[["pistol", 8]]`  | 场上有 `pistol` 标签 → 自己 +8 瓶盖                           |
| 马格南弹 | `connectItem_type` | `[["magnum", 12]]` | 同上                                                          |
| 急救喷雾 | `connectItem_type` | `[["medical", 6]]` | 场上有**别的**医疗用品 → +6 瓶盖                              |
| 雪茄     | `connectItem_type` | `[["luxury", 10]]` | 场上有别的奢侈品 → +10 瓶盖；只有它自己时不加成（自身被排除） |
| 瞄准镜   | `connectItem_id`   | `[["Rifle", 60]]`  | 场上有狙击枪 → 瞄准镜 +60 瓶盖                                |

加成上限由 `CONNECT_BONUS_CAP_PCT`（1.6，当前 30）控制：`gain = min(声明值, base × 30%)`。底价 100 的货最多加 30，底价 20 的货最多加 6。

## 3　状态与流程

**这段要回答**：一件货从出现到消失经历什么。

### 3.1　物品的一生

```text
定义表 ItemDef（静态，永不变）
  └─ 实例 ItemInstance（每次拿出来都新建）
       ├─ 在货架上：只存在库存数字，没有实例
       ├─ 在手上（pending）：已扣库存，实例存在
       ├─ 在箱内（placed）：占格，归属 owner
       ├─ 在枪内：变成目标的 magRounds，不是独立实例
       └─ 消失：成交 / 治疗消耗 / 装弹清零 / 合成消耗 / 被收租搬走
```

### 3.2　取出与收回的时序

```text
从货架拖出
   ↓ takeFromStock()          ← 这一刻就扣库存
   ↓ 生成实例（rounds / magRounds 初始化）
手上悬着 / 放进箱子（都不再动库存）
   ↓ 收回货架 → refundToStock(剩余发数；枪还要退子弹)
   ↓ 成交     → 不返还（已经卖了）
```

### 3.3　装弹时序

```text
拖弹药到枪上 → findInteraction() 判定 → 显示「松手 为{枪名}装弹 N 发」
   ↓ 松手 → 复核来源还在
   ↓ 目标 magRounds += N；loadedAmmoId = 弹 id
   ↓ 来源 −N（货架 / 箱内 / 手上）；打空的那件直接销毁
```

### 3.4　合成时序

```text
拖红（或绿）到另一件上 → 判定 → 提示「松手 组合草药」
   ↓ 预演：先把两件拿掉，看产物能不能放在目标位置
   ↓ 能放 → 消耗两件、新建 herb_mixed、选中新产物
   ↓ 不能放 → 整笔取消，提示「先把旁边挪开」
```

### 3.5　与其它系统的接口

| 本系统提供                            | 给谁 | 用途                       |
| ------------------------------------- | ---- | -------------------------- |
| `ItemDef`（含 `cells`）               | S01  | 形状与旋转                 |
| 实例读写 / `owner`                    | S03  | 拖拽、回收                 |
| 开局库存表、自带物品的实例创建        | S04  | 客人生成                   |
| `value` / `rounds` / `magRounds`      | S05  | 定价、弹药按发计、装弹增值 |
| `connectItem_type` / `connectItem_id` | S05  | 条件协同加成（2.9）        |
| 治疗表 `HEAL_RULES`                   | S05  | 治疗奖励折算               |

## 4　交互与表现

**这段要回答**：客户端要显示什么，什么时候变。

### 4.1　角标

| 位置   | 显示                    | 说明                                                   |
| ------ | ----------------------- | ------------------------------------------------------ |
| 左上角 | 归属（玩家 / 客人）     | 如果是客人的物品，需要标出来归属，玩家的物品则无需标记 |
| 右下角 | 弹药剩余发数 / 枪内发数 | 只在有 `rounds` / `magRounds` 时显示                   |

注意角标一定要出现在物品占用的格子内

规则在S01-网格与容器 2.9内，这里也搬一个摘要过来：

- 左上角标记：沿包围盒最左一列往**下**找，落在第一个真正被物品占用的格
- 右下角角标：沿包围盒最下一行往**左**找，落在第一个真正被物品占用的格

### 4.2　交互提示文案

在玩家拖动物品时候，满足条件会显示在幽灵物品（看S3）上方一些，不能被手指挡住

| 场景   | 文案                         |
| ------ | ---------------------------- |
| 装弹   | 「松手 为{枪名}装弹」        |
| 合成   | 「松手 组合{物品名}」        |
| 治疗   | 「松手 给他治疗」            |
| 不能治 | 直接显示原因（红色草药那句） |

### 4.3　音效

| 事件 | 音效               |
| ---- | ------------------ |
| 装弹 | 弹匣上膛的「咔哒」 |
