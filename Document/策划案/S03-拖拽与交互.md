## 0　摘要

**这段要回答**：这个系统在整局里负责什么，不负责什么，谁依赖它。

### 0.1　一句话职责

**把连续的指针事件翻译成离散的意图**——选中、拖拽、放置、交互、取消——然后交给对应系统执行。它是全游戏**唯一读指针的地方**。

### 0.2　不做什么

| 不做                             | 谁做           |
| -------------------------------- | -------------- |
| 不判断这个形状能不能放在这个锚点 | S01 网格与容器 |
| 不改库存、不建实例、不定归属     | S02 物品与库存 |
| 不决定装弹装几发、合成出什么     | S02 物品与库存 |
| 不算成交价                       | S05 结算       |
| 不画幽灵、不做动画               | 客户端表现     |

### 0.3　依赖

- 上游：S01（几何判定）、S02（实例与库存）、当前阶段（由状态机提供）、当前客人（S04）。
- 下游：客户端表现层读取本系统产出的高亮状态与幽灵位置。

### 0.4　验收标准

一句话：**任何一次按下—抬起，最终都落到 9 种归宿之一，且不会出现"两件东西同时在手上"。**

可测三条：

1. 任意手势序列结束后，`pending` 最多只有一件。
2. 手指位移小于阈值时不会产生任何状态变更。
3. 拖拽中途被打断（失焦、阶段切换），库存与箱子里的东西都与拖拽前一致。

## 1　数据

**这段要回答**：有哪些字段，类型是什么，谁写谁读。

### 1.1　拖拽会话 `DragSession`

一次拖拽从按下开始、到抬起结束，只存在一个会话。

| 字段                | 类型                      | 含义                                                             |
| ------------------- | ------------------------- | ---------------------------------------------------------------- |
| `pointerId`         | int                       | 只响应这个 id 的事件，其它手指一律忽略（大概是用于防止多指拖拽） |
| `kind`              | `rail / placed / pending` | 来源：货架 / 箱内 / 手上                                         |
| `itemId`            | string                    | 物品定义 id                                                      |
| `instanceId`        | string?                   | 来源是箱内时才会有                                               |
| `rot`               | 0~3                       | 拖拽开始时该物品的朝向                                           |
| `startX` / `startY` | number                    | 按下时的屏幕坐标，用来算位移                                     |
| `active`            | bool                      | 是否已越过拖拽阈值                                               |
| `anchor`            | `{x,y}`?                  | 当前吸附到的锚点；不在容器内时为 null                            |
| `cells`             | `{x,y}[]`                 | 当前锚点下占的绝对格子                                           |
| `valid`             | bool                      | 当前锚点是否合法（S01 判定）                                     |
| `interactionTarget` | string?                   | 指针正压着的、可交互的另一件实例 id                              |
| `overPortrait`      | bool                      | 指针是否压在客人立绘上                                           |
| `heal`              | HealPreview?              | 这件医疗用品能给当前客人用成什么                                 |
| `dropZone`          | `event / dispatch / null` | 指针压在哪个投放区上                                             |
| `ghost`             | 视图对象?                 | 跟手的半透明幽灵，归客户端表现                                   |

### 1.2　选中态 `Selection`

| 值                            | 含义                 | 旋转按钮                     |
| ----------------------------- | -------------------- | ---------------------------- |
| `{kind:'rail', itemId}`       | 选中了货架上的一种货 | 显示，只改"下次拿出来的朝向" |
| `{kind:'placed', instanceId}` | 选中了箱内的一件     | 显示在它上方                 |
| `{kind:'pending'}`            | 手上有件悬空的东西   | 显示在它上方                 |
| `null`                        | 没选中               | 隐藏                         |

同一种货的朝向会被记住：下次从货架拿出来就是上次转到的方向。

### 1.3　常量

| 常量                  | 值   | 说明                                     |
| --------------------- | ---- | ---------------------------------------- |
| `DRAG_THRESHOLD`      | 6 px | 位移小于它算点击，大于等于算拖拽         |
| `CONTAINER_TOLERANCE` | 8 px | 指针在容器边缘外这个距离内，仍算在容器内 |
| 磁吸半径              | 1 格 | 定义在 S01 2.6，本系统调用               |

### 1.4　阶段准入

不同阶段允许从货架拖不同东西，其余一律拒绝并提示。

| 阶段                     | 能从货架拖什么             | 拒绝时的提示                      |
| ------------------------ | -------------------------- | --------------------------------- |
| 装货中（filling）        | 任何东西                   | —                                 |
| 事件处理中（event）      | 任何东西（用于交付）       | —                                 |
| 派遣配置中（dispatch）   | 任何东西（用于交给拾荒者） | —                                 |
| 对白 / 剧本中（talking） | 允许拖，但默认被客人拒绝   | 「现在他不想交易」；剧本指定接受的物品除外 |
| 结算中                   | 不允许                     | 「正在结账」                      |
| 等客人中 / 打烊 / 已结束 | 不允许                     | 「先叫下一位客人」/「先开门营业」 |

## 2　规则

### 2.1　点击与拖拽的分界

```text
pointerdown:
    记录 pointerId、起点、来源 kind、当前 rot
    进入 pressed 状态（还没开始拖）

pointermove（只认同一个 pointerId）:
    if 未激活 且 位移 < DRAG_THRESHOLD: 忽略，仍算点击
    if 未激活 且 位移 >= DRAG_THRESHOLD: 激活拖拽，生成幽灵
    激活后每帧重算一次「落点」

pointerup:
    未激活 → 按点击处理（2.4）
    已激活 → 按松手归宿处理（2.3）
```

### 2.2　每帧的判定顺序

> 脚哥：一般来说这个判定顺序会让UI射线自动解决了，这里就明确一下判定优先级而已

**核心规则：每帧从上往下取第一个命中的，命中后不再往下判。**

```text
1. 投放区（事件面板 / 派遣面板）
2. 客人立绘
3. 另一件物品（且这件东西与它之间确实有交互规则）
4. 容器内的格子（含磁吸）
5. 货架区域
6. 以上都不是
```

这条顺序解决三个具体的打架：压在枪上不会被当成"落在枪下面的格子"；压在立绘上不会被当成"落在客人身后的格子"；压着投放区时整块面板高亮而不是逐格高亮。

### 2.3　松手后的归宿

| #   | 松手位置     | 来源             | 结果                                                                                |
| --- | ------------ | ---------------- | ----------------------------------------------------------------------------------- |
| 1   | 事件投放区   | 货架             | 交付给事件 / 交给拾荒者                                                             |
| 2   | 事件投放区   | 箱内 / 手上      | 异常，拒绝，提示「只能从货架上拿新的给他」。<br/>如果是手上的物品有限尝试丢回货架内 |
| 3   | 客人立绘     | 任意             | 尝试治疗并消耗，失败则退回原处                                                      |
| 5   | 可合成物品   | 任意             | 尝试装弹 / 合成（规则在 S02）                                                       |
| 6   | 容器内合法格 | 任意             | 放下 / 移动                                                                         |
| 7   | 容器内非法格 | 任意             | **悬空**：不退回原处，留在松手的位置等玩家旋转                                      |
| 8   | 货架         | 箱内 / 手上      | 收回库存                                                                            |
| 9   | 货架         | 箱内但归属是客人 | 拒绝，弹回原格（客人的东西不能收回）                                                |
| 10  | 空白处       | 货架             | 只取消选中，提示「拖到收银台的格子里才算放下」                                      |

第 7 条是有意为之：放不下时**不退回原处**，而是悬在松手的位置。玩家可以直接点旋转按钮再试，不用重新找位置。

### 2.4　选中

```text
点货架上的货      → 选中（kind = rail）
点箱内的一件      → 选中该实例，旋转按钮浮到它上方
点空格子          → 只取消选中，不移动任何已放好的东西
点以上以外的地方  → 取消选中；手上悬着的那件回货架
```

- 手上已经悬着一件时再拖货架的另一件：**先把手上那件还回库存**，再拿新的。
- 客人的东西悬在手上时，**锁住其它选中**，避免把客人的货和自己的一起操作。

> 人话：同时只能有一个物品在选中状态。选中的物品能够旋转，再次拖动，或者拖到无法置入的位置时在原地进入悬浮状态
>
> 悬浮状态下的物品被取消选中时会尝试放回货架，如果这是客人的物品就不能退出悬浮状态并提示
>
> 这里的描述可能有些抽象了，目前以demo的操作手感为准

### 2.5　旋转

```text
rail 选中:   只改 state.rotation[itemId]，影响"下次拿出来"的朝向
pending:     转 90° → 先看原地 → 再找相邻一格 → 放得下就落位，否则继续悬着
placed:      转 90° → 原地 → 相邻一格 → 实在放不下就转成悬空（格子让出来）
```

- 旋转按钮的位置由客户端表现决定（浮在物品上方），本系统只提供「当前选中项」与「旋转动作」。
- 旋转不受拖拽阈值影响，是点击行为。

### 2.6　中断

| 情况                               | 处理                             |
| ---------------------------------- | -------------------------------- |
| `pointercancel`                    | 结束拖拽，不落格；悬空物保持原位 |
| 窗口失焦（blur）                   | 同上                             |
| 另一个 pointerId 的移动            | 忽略                             |
| 拖拽途中阶段变化（成交、事件弹出） | 结束拖拽，不落格                 |

中断的共同要求：**状态不变**。已经扣掉的库存不回补、已经悬空的东西不消失。

## 3　状态与流程

**这段要回答**：一次手势经历哪些状态。

### 3.1　状态机

```text
idle ──pointerdown──▶ pressed ──move ≥ 6px──▶ dragging ──pointerup──▶ resolving
  ▲                      │                        │                      │
  │                      └──pointerup（未激活）──▶ 点击逻辑 ──────────────┤
  │                                               │                      │
  └───────────────── pointercancel / blur ◀───────┘                      │
  └──────────────────────────── 结果写回状态 ◀───────────────────────────┘
```

### 3.2　一次拖拽的时序

```text
按下货架上的手枪
   ↓ 记录 pointerId、起点、朝向、来源=rail
移动（>6px）→ 生成幽灵，追手
   ↓ 每帧：
   ↓   cellFromPoint() 换算格子
   ↓   指针在容器内（含 8px 容差）吗？不在 → anchor = null
   ↓   clampAnchor() 夹取，再 canPlaceCells() 判合法（S01）
   ↓   命中交互目标 / 立绘 / 投放区时，优先级更高，直接改提示
抬起
   ↓ 合法 → 落格，库存已在"拿出"时扣过（S02）
   ↓ 非法 → 悬空在松手处
```

### 3.3　与其它系统的接口

| 本系统消费                                                      | 来自        | 用途           |
| --------------------------------------------------------------- | ----------- | -------------- |
| `clampAnchor` / `canPlaceCells`                                 | S01         | 磁吸与合法性   |
| `takeFromStock` / `placeFromRail` / `parkFromRail` / `takeBack` | S02         | 落子与回收     |
| `findInteraction` / `applyInteraction`                          | S02         | 装弹与合成     |
| `healPreviewFor` / `healCustomer`                               | S02         | 治疗           |
| 当前阶段 / 当前客人                                             | 状态机、S04 | 准入与治疗目标 |

## 4　交互与表现

**这段要回答**：客户端要显示什么，什么时候变。

### 4.1　幽灵

| 状态       | 表现                                         |
| ---------- | -------------------------------------------- |
| 跟手       | 半透明，无延迟，位置 = 指针位置减去抓取偏移  |
| 吸附到格子 | 透明度再降一档，表示"已对齐"（不是"已放下"） |
| 不合法     | 不改变幽灵颜色，改由落点预览显示红色         |

### 4.2　高亮

| 对象     | 时机                   | 表现                           |
| -------- | ---------------------- | ------------------------------ |
| 落点预览 | 指针在容器内           | 合法绿、非法红                 |
| 投放区   | 指针压在上面           | 整块面板高亮                   |
| 客人立绘 | 指针压在上面           | 边框高亮；能用时高亮为可治疗   |
| 交互目标 | 指针压着可交互的另一件 | 该件描边                       |
| 货架     | 指针压在上面           | 整条货架高亮，表示"松手就收回" |

### 4.3　提示文案

| 场景                      | 文案                                 |
| ------------------------- | ------------------------------------ |
| 拖到空白                  | 「拖到收银台的格子里才算放下」       |
| 拖到立绘但不能回复生命值  | 「他需要的是药品，别的东西治不了伤」 |
| 把箱内/手上的东西拖去交付 | 「只能从货架上拿新的给他」           |
| 阶段不允许                | 见 1.4 表                            |

### 4.4　音效

| 事件            | 音效                       |
| --------------- | -------------------------- |
| 拿起            | 轻"唰"（很轻，不要每帧响） |
| 放置成功        | 同 S01                     |
| 放置失败 / 弹回 | 同 S01 的非法音            |
| 交互成功        | 同 S02 的装弹 / 合成音     |

## 5　边界与异常

| #   | 情况                               | 期望行为                                           |
| --- | ---------------------------------- | -------------------------------------------------- |
| 1   | 位移 5px 就松手                    | 视为点击，不触发拖拽                               |
| 2   | 拖出容器范围                       | `anchor = null`，按"空白"处理：回原位或取消选中    |
| 3   | 拖到容器边缘外 8px 内              | 仍算在容器内                                       |
| 4   | 客人自带的东西拖到货架             | 拒绝，弹回原格                                     |
| 5   | 拖到另一件物品，但两者没有交互规则 | 不作交互，继续按落格判定                           |
| 6   | 拖到已满弹匣的枪上                 | 没有交互提示，继续按落格判定                       |
| 7   | 拖拽中第二根手指按下               | 忽略（pointerId 不匹配）                           |
| 8   | 拖拽中窗口失焦                     | 中断，状态不变                                     |
| 9   | 拖拽中客人成交 / 事件弹出          | 中断，状态不变                                     |
| 10  | 手上已有悬空件，又去拖货架另一件   | 先前那件先还回库存，再拿新的                       |
| 11  | 拖手上的悬空件                     | 走 `movePending`：放得下就落位，否则换位置继续悬着 |
| 12  | 把箱内的东西拖到非法位置           | 转成悬空：不销毁、不扣库存、格子让出来             |
| 13  | 旋转后放不下                       | 保持悬空，不落格                                   |
| 14  | 箱子空着就成交                     | 与拖拽无关，由 S05 拒绝                            |
