## 0　摘要

**这段要回答**：这个系统在整局里负责什么，不负责什么，谁依赖它。

### 0.1　一句话职责

负责「今天出门」这个选项的全部内容：**滚几张地图 → 玩家挑一个 → 按风险结算战利品 → 入库**。

### 0.2　不做什么

| 不做                     | 谁做               |
| ------------------------ | ------------------ |
| 不判断物品能不能放下     | S01 网格与容器     |
| 不管库存的历史与守恒     | S02 物品与库存     |
| 不决定这些东西值多少钱   | S05 结算           |
| 不决定今天开不开门       | 状态机 / 日程      |
| 不画地图、不做图钉       | 客户端表现         |
| 不管理「到访记录」的展示 | S08 笔记与线索     |

### 0.3　依赖

- 上游：S02（物品定义、`rounds` 与入库单位）、S04（声望，只影响后续派遣，不影响本系统）。
- 下游：S02（写库存）、S08（首次到访写入地点页）。

### 0.4　验收标准

一句话：**出门一趟，回来一定有一袋货（15~40 件），而且不会因为运气差到一件不剩。**

可测三条：

1. 任意一次结算，入库件数（弹药按盒折算）落在 15~40 之间。
2. 风险命中也最多丢到 15 件，不会清空。
3. 弹药入库时按「发」记账（盒数 × 每盒发数）。

## 2　规则

**这段要回答**：地图怎么滚、货怎么算、坏事怎么发生。

### 2.1　滚地图

```text
候选数量 = min(地点总数, 随机(4, 6))
不重复地抽这么多个地点
位置：落在 3×3 的抖动网格上（每格一个，互不重叠）
     x = 16 + 列×32 + 随机(-5, 5)
     y = 20 + 行×28 + 随机(-4, 4)
```

用网格而不是纯随机，是为了让图钉不叠在一起、也不会全挤在角落。

### 2.2　选地点

玩家点一个图钉，看完「可能搜到什么 / 风险」之后再确认。**确认之前不会结算**，可以换。

### 2.3　战利品

```text
逐条判 chance：
    命中 → 件数 = 随机(min, max)
一件都没命中 → 强制给第一条一个随机件数（不让人白跑）
总量平衡：把件数加起来，不够 15 就轮流加，超过 40 就从有多件的条目里削
```

平衡这一步是必须的：地点表里各条目的 min/max 只是"倾斜程度"，真正的产量由 15~40 这条硬线决定。

### 2.4　风险

```text
命中概率 = 地点的 risk
没命中 → 平安回店
命中 → 55% 丢货 / 45% 被抢钱

丢货：
    可丢预算 = 当前件数 − 15        // 永远留 15 件
    随机挑一半的条目，每样丢一半（至少 1 件），总丢量不超过预算
    如果实际什么都丢不掉 → 记一条"摔了一跤，好在包抱得紧"的日志

抢钱：
    损失 = min(身上现金, 随机(40, 40 + 天数 × 20))
    钱为 0 时记"有人想抢钱，可你身上一个瓶盖都没有"
```

### 2.5　入库

```text
普通物品：库存 += 件数
弹药：    库存 += 件数 × rounds      // 库存按「发」记（S02 1.3）
```

### 2.6　占掉当天

出门即消耗当天：不能营业、不能接客。**派遣（S07）不占当天**，两者可以同时进行。

### 2.7　与笔记联动

某个地点**第一次**被选中结算时，写入 `visitedLocations[地点id] = 当前天数`，S08 的地点页从此解锁这一页。

## 3　状态与流程

**这段要回答**：一次出门经历什么。

### 3.1　时序

```text
今天选「外出搜刮」
   ↓ 滚 4~6 个地点 → 地图显示图钉
   ↓ 玩家点一个 → 弹出「可能搜到 / 风险」
   ↓ 确认
   ↓ 逐条滚战利品 → 平衡到 15~40 件
   ↓ 滚风险 → 丢货或抢钱
   ↓ 日志逐条播放
   ↓ 入库（弹药折算成发）、扣钱
   ↓ 写入到访记录（S08）
   ↓ 日结：换天
```

### 3.2　与其它系统的接口

| 本系统消费 | 来自 | 用途 |
| --- | --- | --- |
| `LocationDef` / `LootEntry` | S02 物品表 | 产出什么、给几件 |
| 当前天数 | 状态机 | 抢钱额度、到访记录 |
| 当前现金 | 存档 | 抢钱上限 |

| 本系统产出 | 给谁 | 用途 |
| --- | --- | --- |
| `gains` | S02 | 写库存 |
| `visitedLocations` | S08 | 解锁地点页 |
| `log` | 客户端 | 逐条播放 |

## 4　交互与表现

**这段要回答**：玩家看到什么。

### 4.1　地图

| 元素 | 规则 |
| --- | --- |
| 图钉 | 每个地点一个，显示地点名与风险档位（低/中/高） |
| 选中 | 点一下弹出详情卡，再确认才开始结算 |
| 已选 | 结算后图钉变灰，不能重选 |

### 4.2　日志

一条一条往下推，不是一次全出：翻到的东西用正文字色，丢东西用暗红，钱用金色。玩家可以点一下加速。

### 4.3　音效

| 事件 | 音效 |
| --- | --- |
| 选中地点 | 图钉"叮" |
| 翻到东西 | 翻箱的窸窣声 |
| 丢东西 / 被抢 | 低沉的撞击声 |

## 5　边界与异常

| # | 情况 | 期望行为 |
| --- | --- | --- |
| 1 | 一件都没命中 | 强制给第一条一个随机件数，不空手 |
| 2 | 命中数不足 15 件 | 轮流加，补到 15 |
| 3 | 溢出 40 件 | 从有多件的条目里削 |
| 4 | 风险命中但已只剩 15 件 | 丢不了货，改判抢钱 |
| 5 | 身上没有现金 | 抢钱损失为 0，仍播日志 |
| 6 | 同一地点第二次来 | 正常搜刮，但笔记不再重复记录 |
| 7 | 已结算后又点确认 | `done` 拦截，不重复入库 |
| 8 | 地点表里的物品 id 不存在 | 跳过该条目，不崩 |
| 9 | 弹药产出 | 入库按「发」，日志写"XX 发" |
| 10 | 出门当天又想营业 | 不允许：出门已消耗当天 |

## 6　验收用例

| # | Given | When | Then |
| --- | --- | --- | --- |
| 1 | 今天选出门 | 滚地图 | 出现 4~6 个不重复地点，图钉不重叠 |
| 2 | 选中「警局」（风险 40%） | 结算 | 战利品件数在 15~40 |
| 3 | 风险命中且当前 30 件 | 结算 | 最多丢 15 件，剩 15 |
| 4 | 风险命中且当前 15 件 | 结算 | 不丢货，改为抢钱 |
| 5 | 现金 0 | 风险命中抢钱 | 损失 0，日志说明没钱 |
| 6 | 产出霰弹包 3 盒（每盒 20 发） | 入库 | 库存 +60 发 |
| 7 | 第一次到访医院 | 结算完成 | 笔记地点页解锁「医院」，记录当天日期 |
| 8 | 第二次到访医院 | 结算完成 | 正常搜刮，笔记日期不变 |
