## 0　摘要

**这段要回答**：这个系统在整局里负责什么，不负责什么，谁依赖它。

### 0.1　一句话职责

记录玩家**知道的事**——遇到过的客人、听过的传闻、去过的地方——并在对白里充当**推进条件**：客人等某条线索时，把它出示给他。

### 0.2　不做什么

| 不做                       | 谁做               |
| -------------------------- | ------------------ |
| 不写剧本、不决定对白内容   | S04 客人与特殊客人 |
| 不决定去哪搜刮、搜到什么   | S06 外出搜刮       |
| 不管理库存                 | S02 物品与库存     |
| 不画笔记界面               | 客户端表现         |

### 0.3　依赖

- 上游：S04（剧本回合的 `clue` 需求）、S06（到访记录）。
- 下游：S04（出示命中后推进对白）、S03（笔记打开时禁止拖拽）。

### 0.4　验收标准

一句话：**玩家能翻到"我确实知道这件事"的一页，并且在对的时机把它递给对的人。**

可测三条：

1. 没到访过的地点，笔记里**完全不出现**（不是灰着，是不渲染）。
2. 出示的笔记不在客人的 `accepts` 里时，对白不推进。
3. 同一件事不会重复记两页。

## 1　数据

**这段要回答**：笔记里存什么、一页长什么样。

### 1.1　笔记状态 `NotesState`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `open` | bool | 笔记是否打开 |
| `tab` | enum | 当前页签：`customers` / `clues` / `locations` |
| `expandedId` | string? | 当前展开的那一页 |
| `met` | 数组 | 遇到过的特殊客人（按遇到顺序） |
| `visitedLocations` | `Record<id, day>` | 到访过的地点 → 第一次去的日子 |
| `lastPresented` | `{noteId, accepted, day}?` | 最近一次出示的结果 |

### 1.2　一页笔记 `NoteEntryDef`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 唯一键，见 2.2 |
| `kind` | enum | `clue` 传闻 / `location` 地点（`customer` 由 `met` 生成） |
| `title` | string | 标题 |
| `locationId` | string? | 地点页对应哪个地点 |
| `defaultUnlocked` | bool? | 不看任何条件就能看到 |
| `detail` | string[]? | 展开后的段落；不给就按地点数据现生成 |

### 1.3　遇到过的客人 `MetCustomerNote`

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `customerId` | string | 客人 id |
| `day` | int | 第一次遇到是第几天 |
| `name` / `title` | string | 名字与头衔 |
| `request` / `aside` | string | 他当时说的需求与旁白 |

### 1.4　客人的线索需求 `CustomerClueNeed`

挂在剧本的某一回合上：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `accepts` | string[] | 这一回合接受哪些笔记 id |

### 1.5　常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| 页签数量 | 3 | 客人图鉴 / 传闻线索 / 搜刮地点 |
| 出示上限 | 每回合 1 次 | 出示成功即推进，不消耗笔记 |

## 2　规则

**这段要回答**：什么能被记下来、什么时候能看见、怎么出示。

### 2.1　三个页签与可见性

| 页签 | 内容 | 可见条件 |
| --- | --- | --- |
| 客人图鉴 | 遇到过的**特殊客人** | 见过一页就有一页 |
| 传闻线索 | 世界规则类的情报 | 默认解锁（2.3） |
| 搜刮地点 | 每个地点一页 | **第一次到访后**解锁；"保护伞公司"这类笔记专属地点写死解锁 |

**锁定的条目完全不渲染**，不是灰显——玩家不该知道自己"还差几页"。

### 2.2　条目 id 规范

```text
客人：customer:<customerId>
地点：location:<locationId>
线索：clue-<name>            // 例：clue-rent
```

id 是内容层（剧本）和笔记层**共用的唯一字符串**，两边都不许各写一套。

### 2.3　线索从哪来

```text
默认解锁：开局就在册（例如"送货员的记事本""黑鸦帮的租子""水塔议会的水税"）
事件获得：由剧本/事件写入（预留）
到访解锁：S06 结算时写 visitedLocations，地点页随之出现
```

当前实现里"传闻线索"页的三条都是默认解锁；**获得线索的通用入口还没接**，只有一个约定：往 `met` / `visitedLocations` 里写，页面自然就有了。

### 2.4　出示

```text
条件：
    当前客人有对白，且当前回合带 clue
    玩家打开笔记，点某一页的「出示」

判定：
    这一页的 id ∈ clue.accepts  → 命中：推进一回合，合上笔记
    不在 accepts 里             → 未命中：记录 lastPresented{accepted:false}，不推进

结果：
    命中不消耗笔记（可以反复给不同的人看）
```

### 2.5　提示

- 客人正在等线索时，笔记按钮会**轻微呼吸**（`data-clue=true`），提示"这里有答案"。
- 只有当前回合带 `clue` 时才显示「出示」按钮；平时展开只读。

### 2.6　与拖拽的关系

笔记打开时，**不接受任何拖拽**（S03 的准入在打开笔记这一点上直接短路）。否则会出现"一边翻书一边把货拖到箱子里"的错位。

## 3　状态与流程

**这段要回答**：一页笔记从无到有、从有到用。

### 3.1　获得

```text
遇到特殊客人 → 写一条 met（同一个人只记一次）
第一次到访地点 → 写 visitedLocations[地点] = 当天
剧本/事件给线索 → 写进线索册（预留接口）
```

### 3.2　使用

```text
客人说到需要线索的那句
   ↓ 笔记按钮呼吸
   ↓ 玩家打开笔记 → 切到对应页签 → 展开那一页
   ↓ 点「出示」
   ↓ 命中 → 对白推进 → 笔记合上
   ↓ 未命中 → 停在原回合，可再试
```

### 3.3　与其它系统的接口

| 本系统消费 | 来自 | 用途 |
| --- | --- | --- |
| 剧本回合的 `clue` | S04 | 判断当前是否在等线索 |
| 到访记录 | S06 | 解锁地点页 |
| 遇到客人的事件 | S04 | 写客人图鉴 |

| 本系统产出 | 给谁 | 用途 |
| --- | --- | --- |
| 出示命中 | S04 | 推进对白 |
| `lastPresented` | 调试 / 存档 | 回放与问题排查 |

## 4　交互与表现

**这段要回答**：玩家怎么翻、怎么递。

### 4.1　笔记本

| 元素 | 规则 |
| --- | --- |
| 入口 | 屏幕边缘一本可以翻开的书（当前在收银台旁边） |
| 页签 | 三个，切换时列表滚回顶部 |
| 条目 | 一行一条，点开才显示正文；一次只展开一条 |
| 空页 | 客人图鉴空时提示"还没遇到什么特别的人" |

### 4.2　出示

| 元素 | 规则 |
| --- | --- |
| 按钮 | 只在客人等线索、且展开某一页时出现 |
| 位置 | 固定在展开内容的底部，不随滚动跑 |
| 反馈 | 命中：合上笔记、对白推进；未命中：按钮抖一下，不扣东西 |

### 4.3　音效

| 事件 | 音效 |
| --- | --- |
| 翻开 / 合上 | 纸页摩擦 |
| 命中 | 一记轻"叮" |
| 未命中 | 很轻的"唔"（不要做成失败音） |

## 5　边界与异常

| # | 情况 | 期望行为 |
| --- | --- | --- |
| 1 | 同一个客人遇到两次 | 图鉴只记第一次 |
| 2 | 同一地点去两次 | 日期保持第一次，不更新 |
| 3 | 出示不在 accepts 里的笔记 | 不推进，记 `accepted:false`，可再试 |
| 4 | 客人当前回合没有 `clue` | 不显示「出示」按钮 |
| 5 | 笔记 id 不存在 | 出示无效，不报错 |
| 6 | 笔记打开时拖货 | 拖拽被拦截 |
| 7 | 对白走完后再出示 | 回合已过，不再接受 |
| 8 | 地点从未到访 | 该页完全不出现 |
| 9 | 客人离场后线索还在册 | 保留，不删除 |
| 10 | 页签切换时正展开某条 | 收起展开项，回到列表顶部 |

## 6　验收用例

| # | Given | When | Then |
| --- | --- | --- | --- |
| 1 | 第一次遇到特殊客人 | 打开客人图鉴 | 多出他的一页，含头衔与第一次见面的天数 |
| 2 | 同一客人第二天又来 | 再打开 | 仍然只有一页，天数不变 |
| 3 | 从未去过医院 | 打开地点页 | 找不到「医院」这一页 |
| 4 | 第一次去完医院 | 打开地点页 | 出现「医院」，标注第一次到访日期 |
| 5 | 客人当前回合等 `location:umbrella` | 出示该页 | 对白推进，笔记合上 |
| 6 | 同上，出示「黑鸦帮的租子」 | 出示 | 不推进，记录 `accepted:false` |
| 7 | 客人没在等线索 | 打开笔记 | 没有「出示」按钮，只有正文 |
| 8 | 笔记打开状态 | 拖一件货到箱子 | 拖拽被拦截 |

## 7　待定与风险

| # | 问题 | 说明 |
| --- | --- | --- |
| 7.1 | 线索的获得途径 | 当前只有默认解锁；需要一套"剧本/事件写入线索"的通用接口 |
| 7.2 | 线索是否会被消耗 | 当前不消耗（可重复出示）；若以后要做"一次性钥匙"，要改出示规则 |
| 7.3 | 客人图鉴是否收录随机客人 | 当前只收特殊客人；随机客人有几百种身份，收进来会淹掉 |
| 7.4 | 地点页是否记到访次数 | 当前只记第一次；如果做"搜过几次"要改数据结构 |
